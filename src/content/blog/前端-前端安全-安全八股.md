## 1.  **XSS（Cross-Site Scripting）跨站脚本攻击**
### 1. XSS的概念与分类
**XSS（Cross-Site Scripting，跨站脚本攻击）指的是攻击者向网页注入恶意脚本，让这些脚本在其他用户的浏览器中执行，从而达到窃取 Cookie、伪造身份、执行恶意操作等目的。**
即：恶意用户利用某些网站的漏洞，来攻击正常用户
 
常见的 XSS 类型有三种：反射型、存储型和 DOM 型：

- > **反射型 XSS**：恶意脚本通过 URL 传入，服务器原样输出到页面中，用户一访问这个链接就会被攻击。
- > **存储型 XSS**：恶意脚本被保存到数据库，比如评论区、帖子内容，其他用户访问页面时就会自动执行，是危害最大的一种。
- > **DOM 型 XSS**：不经过后端，前端 JS 在处理 DOM 时不安全地把不可信数据插入到了页面中导致执行。

## **2. CSRF（Cross-Site Request Forgery）跨站请求伪造**
### 1. CSRF的概念和原理
**CSRF（Cross-Site Request Forgery，跨站请求伪造）是：攻击者“冒充用户”，在用户不知情的情况下，利用用户已经登录的状态，向网站发出恶意请求的一种攻击**

CSRF 的前提是浏览器的一个特性：

**对某个域已设置的 Cookie，在访问这个域的任意请求中，浏览器都会自动附带上 Cookie**（只要没被 SameSite 限制）。即==同源的请求会自动携带 cookie，这是导致 CSRF 攻击能成立的前提==

这意味着：
你登录了 bank.com，浏览器里存了 bank.com 的登录 Cookie
只要有任何页面（不一定是 bank.com）发出请求到 https://bank.com/...
浏览器就会 **自动带上 Cookie**
服务器只看到一个“正常带登录态的请求”，分不清是你点的，还是被别人偷偷发的  

同源策略只能保护“**读取响应数据**”，但**不能阻止发请求**。

所以跨站请求发出去是没有问题的，这就给了 CSRF 空间。
### 2.CSRF 举例
设想一个场景：

1. 你已经登录了 https://bank.com，且保持登录状态。

	**攻击者准备一个恶意页面**，比如：
	- 一个钓鱼网站    
	- 一篇帖子里的图片
	- 一封邮件里的 img标签 或 form 标签 等
2. 恶意页面中藏着请求到 bank.com 的代码，比如：

```html
<img src="https://bank.com/transfer?to=hacker&money=10000">

```

3. **你用登录状态的浏览器打开了这个恶意页面**。浏览器会尝试加载这张图片，于是访问了对应的 url

```http
GET /transfer?to=hacker&money=10000 HTTP/1.1
Host: bank.com
Cookie: session=用户的登录凭证

```

4. 服务器收到请求，看到了合法的 session Cookie，以为是你本人发起的转账，于是执行操作。
==这就是最典型的 CSRF：**利用你的登录态 + 利用浏览器自动带 Cookie + 伪造你发请求**。==

所以：CSRF 的核心即是，利用浏览器在同源请求下会自动携带 cookie 的特性，获取到用户cookie 中的鉴权信息，从而让伪造用户的请求，让用户在神不知鬼不觉的情况下执行操作
