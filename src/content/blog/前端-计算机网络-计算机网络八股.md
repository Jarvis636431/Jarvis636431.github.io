## **1. HTTP 常见的状态码与含义

### **1xx：信息**
- **100 Continue**：继续发送
### **2xx：成功**
- **200 OK**
- **201 Created**
### **3xx：重定向**
- **301 永久重定向**
- **302 临时重定向**
- **304 Not Modified（缓存命中）**
### **4xx：客户端错误**
- **400 Bad Request**
- **401 Unauthorized**
- **403 Forbidden**
- **404 Not Found**
### **5xx：服务器错误**
- **500 Internal Server Error**
- **502 Bad Gateway**
- **503 Service Unavailable**
## **2. GET 和 POST 的区别？**
- GET 幂等，POST 不幂等
- GET 参数在 URL，POST 在 body
- GET 有长度限制，POST 理论无限
**“本质上 GET/POST 在 TCP 层没有任何区别，是语义区别。”**
## 3. HTTP/1.1、HTTP/2、HTTP/3 的区别
### **HTTP/1.1**
- 管道化→基本被禁用
- 同域名**最多 6 个连接**（浏览器限制）
- 队头阻塞（HOL）
### **HTTP/2**
- **多路复用（一个 TCP 连接走多条流）**
- 二进制帧
- Header 压缩（HPACK）
- Server Push（已被废弃）
### **HTTP/3（QUIC）**
- 基于 **UDP**
- 彻底解决 TCP 队头阻塞（流级别）
- 快速握手
- 更安全，TLS1.3 内置
## **4. TCP 三次握手
### 三次握手流程：**
1. **SYN**：客户端 → 服务端（我要连接）
2. **SYN + ACK**：服务端 → 客户端（收到请求，可以连接）
3. **ACK**：客户端 → 服务端（确认）
### **目的：**
- 确认双方收/发能力正常
- 初始化序列号（ISN）
- 防止旧连接包影响新连接
### 为什么是三次握手不是两次
因为两次无法确认：
- 服务端能否收到客户端消息？
- 客户端能否收到服务端消息？
- 旧 SYN 包是否被重复传送？
## **6. TCP 四次挥手
### 四次：
1. **FIN**（客户端说我不发了）
2. **ACK**
3. **FIN**（服务端发完了，也不发了）
4. **ACK**
### **为什么要四次？**
因为 TCP 是**全双工**，发送和接收关闭要分别确认。
## **7. TCP 为什么需要 TIME_WAIT？**

### **目的：**
1. 确保旧包不影响新连接
2. 确保对方收到最后的 ACK（否则对方会重发 FIN）
TIME_WAIT 默认 **2MSL（最大报文生存时间）**。
## **8. TCP 和 UDP 的区别？**

| **特点** | **TCP**    | **UDP**      |
| ------ | ---------- | ------------ |
| 连接     | 有连接（三次握手）  | 无连接          |
| 是否可靠   | ✔ 可靠       | ❌ 不可靠        |
| 顺序性    | 保证顺序       | 不保证          |
| 速度     | 慢          | 快            |
| 场景     | HTTP/HTTPS | DNS、视频、语音、游戏 |
UDP 支撑 QUIC（HTTP/3)
## 9. 浏览器从输入 URL 到页面渲染经历哪些步骤
1. DNS 解析
2. 建立 TCP 或 QUIC 链接
3. 发送 HTTP 请求
4. 服务器响应 HTML
5. 浏览器解析 HTML（构建 DOM）
6. 下载 CSS、JS（构建 CSSOM、执行 JS）
7. 合成 Render Tree
8. Layout（布局）
9. Paint（绘制）
## 10. DNS 的解析过程
解析域名 → IP，查询流程：
1. 浏览器缓存
2. 操作系统缓存
3. hosts 文件
4. 本地 DNS 服务器
5. 根服务器
6. 顶级域名服务器（.com）
7. 权威 DNS
## 11. CDN 与应用
### **CDN = 内容分发网络**
作用
- 靠近用户，提高访问速度
- 缓存静态资源
- 减轻源站压力
- 可做分布式调度，抗攻击能力强
## **12. HTTPS 是如何保证安全的
通过 **TLS 握手**确保：
- 对称加密（快）
- 非对称加密（安全地交换密钥）
- 证书保证真实性（CA 签名）
**核心：**
> 用非对称加密交换对称密钥，然后全部用对称加密通信。
## **13. 中间人攻击（MITM）是什么？HTTPS 如何防御？**

攻击者拦截并篡改传输。
HTTPS 通过以下方式防御：

1. **公钥加密 + 私钥解密**
2. **证书链**
3. **CA 信任体系**
