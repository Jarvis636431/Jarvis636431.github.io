## **1. 为什么要做性能优化？性能优化的目标是什么？**

**标准回答：**
提高用户体验，提升页面加载速度、交互流畅度，降低资源消耗，提高留存率。真实业务中加载时间直接影响转化率（比如首屏从 3s 优化到 1s 转化率显著提升）。

**扩展补充：**
- Web Vitals：**LCP、FID、CLS、FCP、TTI** 是核心指标。
- 优化不仅针对加载，也包括运行性能（JS 执行）、渲染性能（布局重排）、内存占用（防泄漏）。

## **2. 白屏时间/首屏性能优化有哪些方法？**

**标准回答：**
1. **SSR / SSG / 预渲染**（减少客户端渲染成本）
2. **资源分包、按需加载（code splitting）**
3. **CDN 加速 / 静态资源缓存**
4. **减少关键渲染路径（Critical Rendering Path）**：
    - preload、dns-prefetch、preconnect
5. **减少 JS 体积**：tree-shaking、压缩、polyfill 按需
6. **图片优化**：webp、懒加载、雪碧图
7. **骨架屏 / loading skeleton**（感知速度优化）

**追问：为什么 SSR 可以提升首屏？**
→ SSR 直接返回 HTML 内容，无需等待 JS 执行去构造 DOM。

## **3. 如何减少关键渲染路径（CRP）？是什么？**

**标准回答：**
CRP 是从 HTML 解析到页面可见的整个过程，优化方向：

- 提前加载关键资源：< link rel="preload" >
- 减少阻塞渲染的 JS：defer / async
- CSS 放 head，但拆小、压缩、Critical CSS inline
- 减少字体、第三方脚本阻塞

**可能追问：defer 和 async 区别？**

- async：下载并执行都异步，执行顺序不保证。
- defer：下载异步，但执行在 DOMContentLoaded 前，顺序保证。

## **4. JS 运行性能优化**

**标准回答：**

- **减少主线程压力**：Web Worker、OffscreenCanvas
- **合理使用节流/throttle & 防抖/debounce**
- **避免频繁的 DOM 操作**（使用 DocumentFragment、批量更新）
- **减少重排/回流**：避免频繁读写 offset/scroll
- **虚拟列表（大数据渲染）**
- **使用 requestAnimationFrame** 优化动画

**可能追问：什么会触发重排？**

- 改变布局类属性：width/height/margin/padding/border
- DOM 增删
- window resize、字体加载
## **5. 图片优化方案**

**标准回答：**
- 使用 **WebP、AVIF** 等更小格式
- 使用 **响应式图片**：srcset、sizes
- 图片懒加载：loading="lazy"
- 雪碧图（减少请求）
- Icon 尽量用 **SVG**（矢量可控、可复用）
- CDN 图片裁切、压缩 

**追问：为什么 WebP 更省？**
→ 基于更优压缩算法（预测编码+变换编码）。

## **6. 代码层面优化（减少 bundle 体积）？**

**标准回答：**
- Tree-shaking（未使用的代码删除）
- Code splitting（按需加载）
- babel-polyfill 按需注入
- Terser/Uglify 压缩
- 使用轻量库：lodash-es tree-shake、dayjs 替代 moment
- 移除 devtools & sourcemap 在生产环境

**追问：为什么 tree-shaking 对 CommonJS 不友好？**
→ 因为 CommonJS 是动态 require，无法静态分析依赖。

## **8. 网络层性能优化？**

**标准回答：**

- HTTP/2 多路复用减少队头阻塞
- HTTP/3 基于 QUIC，提升弱网性能
- TCP 连接复用：keep-alive
- Gzip / Brotli 压缩
- CDN 加速（就近访问）

**可能追问：HTTP/2 为什么能提升性能？**

→ 头部压缩 + 多路复用 + 服务端推送（已不常用）。
## **9. React / Vue 运行性能优化？**

**React：**

- useMemo/useCallback 避免不必要渲染
- React.memo
- 虚拟列表
- 懒加载 + Suspense
- 避免在 render 里创建对象
- key 稳定且唯一

**Vue：**

- keep-alive 缓存组件
- computed 缓存
- 避免深度 watcher
- 使用 v-show 代替 v-if（在频繁切换时）
- 虚拟滚动列表
## **10. 大文件上传/下载性能优化？**

**标准回答：**

- 切片上传 + 并发请求
- 秒传（MD5/哈希比对）
- 断点续传（记录已上传分片）
- 文件压缩
- 使用 Service Worker 劫持并缓存文件资源

## 常见的前端性能监控指标？

**Web Vitals：**
- LCP（最大内容绘制）
- FID（首次输入延迟）
- CLS（布局偏移）
- FCP（首次内容渲染）
- TTI（可交互时间）

**监控方式：**

- Performance API
- MutationObserver
- Resource Timing API
- 大厂使用 sentry/web-vitals 上报

## **12. 性能瓶颈一般怎么排查？**
**标准回答：**

- **Chrome DevTools**：Performance、Lighthouse、Coverage
- **网络面板**：大体积资源、N+1 请求
- **Memory**：内存泄漏
- **JS Profile**：长任务（Long Task > 50ms）
- **Coverage**：未使用的 JS/CSS
  
**可能追问：怎么判断是否出现内存泄漏？**
→ heap snapshot 多次对比是否持续上升。
