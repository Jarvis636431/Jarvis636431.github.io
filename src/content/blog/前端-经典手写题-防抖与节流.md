## **为什么需要防抖与节流？**

为了减少高频事件触发：

- scroll（滚动）
- resize（窗口缩放）
- input（实时输入）
- mousemove（鼠标移动）
- keyup / keydown

例如：

搜索输入框实时联想，如果你一边输入一边发请求，可能发几十个请求，浪费资源。
防抖与节流就是为了**限制函数的执行频率，减少无意义的计算和请求**。

## **防抖（Debounce）**

事件触发后 ，等待一段时间再执行，若这段时间内再次触发，重新计时 ➜ **只执行最后一次**
## **✨特点**

- 高频触发中 **只执行最后一次**。
- 常用于：
    - 搜索框实时请求
    - input内容校验
    - 按钮反复点击防止触发提交
## **防抖的基础实现**

```javascript
function debounce(fn, delay = 300) {
  let timer = null;

  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}

```

### **执行流程：**

1. 事件触发 → 清掉上一个定时器
2. 用户不再继续触发 → 等待 delay 后执行回调

## **立即执行版（面试常问：“有没有 immediate”）**

```javascript
function debounce(fn, delay = 300, immediate = false) {
  let timer = null;

  return function (...args) {
    const callNow = immediate && !timer;

    clearTimeout(timer);

    timer = setTimeout(() => {
      timer = null;
      if (!immediate) fn.apply(this, args);
    }, delay);

    if (callNow) fn.apply(this, args);
  };
}

```

- immediate = true：第一次触发立即执行
- 至少 delay 之后才允许再次执行

## **节流（Throttle）**

在一段时间内，只允许事件执行一次 ➜ **只执行“固定频率”，比如每 1 秒最多一次**
## **✨特点**

- 在连续触发中 **每隔固定时间执行一次**
- 常用于：
    - scroll 监听页面滚动
    - resize
    - 拖拽事件 mousemove
    - 高频 DOM 操作
## **✔ 时间戳版节流（leading call）**

```javaScript
function throttle(fn, delay = 300) {
  let last = 0;

  return function (...args) {
    const now = Date.now();
    if (now - last >= delay) {
      last = now;
      fn.apply(this, args);
    }
  };
}

```

### **特点**

- 立刻执行一次（leading）
- 但停止触发后不会再执行（没有 trailing）

## **定时器版节流（trailing call）**

```javascript
function throttle(fn, delay = 300) {
  let timer = null;

  return function (...args) {
    if (!timer) {
      timer = setTimeout(() => {
        timer = null;
        fn.apply(this, args);
      }, delay);
    }
  };
}

```

### **特点**

- 不会立刻执行
- 停止触发后会补一次尾执行（trailing）
## **完整的节流（leading / trailing 可配置）**

```javascript
function throttle(fn, delay = 300, options = { leading: true, trailing: true }) {
  let timer = null;
  let last = 0;

  return function (...args) {
    const now = Date.now();

    if (!last && options.leading === false) {
      last = now;
    }

    const remaining = delay - (now - last);

    if (remaining <= 0) {
      if (timer) {
        clearTimeout(timer);
        timer = null;
      }
      last = now;
      fn.apply(this, args);
    } else if (!timer && options.trailing !== false) {
      timer = setTimeout(() => {
        last = options.leading === false ? 0 : Date.now();
        timer = null;
        fn.apply(this, args);
      }, remaining);
    }
  };
}

```

可以控制：

- **leading**：首次触发是否立即执行
- **trailing**：结束后是否执行最后一次

这是面试中要求你“优化节流”的版本。

## **防抖 vs 节流 的区别**

| **特性**   | **防抖（debounce）** | **节流（throttle）**   |
| -------- | ---------------- | ------------------ |
| 执行次数     | 最后一次（可立即执行）      | 固定频率               |
| 高频触发时    | 永远只执行一次          | 每隔一段时间执行一次         |
| 典型场景     | input 搜索联想       | scroll / resize 优化 |
| 实现原理     | 清除定时器            | 时间戳或定时器            |
| 是否可以首尾控制 | 可以               | 可以（高级实现）           |

## 应用场景

### **什么场景适合防抖？**
- 输入框搜索
- 按钮防重复提交
- 表单实时校验
### **什么场景适合节流？**

- 滚动位置计算
- 大量 DOM 操作
- window.resize
### **防抖和节流能否一起用？**

可以，例如搜索框：
- 输入时防抖搜索
- 滚动结果列表节流渲染
