完成一个能收敛的 LR CTR 模型，还不等于能够处理真实业务数据。真实曝光日志通常具有两个明显特点：点击样本远少于未点击样本，特征数量又可能非常大。

这会带来两个问题：

```text
正负样本严重不平衡 → 指标和概率容易被误解
特征多而数据有限   → 模型容易记住噪声并过拟合
```

这篇文章集中回答两个关键补丁：如何处理类别不平衡，以及如何通过正则化控制过拟合。

## 0. 哪些结论与模型无关

本文同时包含两种知识，需要先明确边界。

### 0.1 搜广推通用基础

下列结论不依赖 LR 的模型结构，换成 FM、DeepFM、DCN、DIN 或其他排序模型仍然成立：

- 低 CTR 下，Accuracy 容易被多数负样本误导；
- 排序、概率预测和阈值分类是三个不同问题；
- AUC 衡量相对排序，PR-AUC 更关注稀少正样本；
- LogLoss 衡量概率质量，ECE 衡量概率与实际频率的一致性；
- 负采样会改变训练分布和模型输出的概率含义；
- 样本加权会改变不同错误对训练目标的贡献；
- 验证集和测试集应尽量保留接近线上场景的真实分布；
- Early Stopping 和超参数选择只能使用验证集；
- 离线指标必须结合数据口径、业务目标和线上成本解释。

这些知识也适用于 CVR、多任务学习和 Learning to Rank。具体指标可能变化，但“先明确任务，再选择口径”的方法不变。

### 0.2 与 LR 或当前实现相关的知识

下列结论不能直接推广到所有模型：

- LR 只能学习输入中已有特征的线性权重，不会自动创建乘法交叉；
- LR 权重的正负方向具有较直接的解释性；
- 当前代码让 `model.py` 返回 logits，并使用 `BCEWithLogitsLoss`；
- 当前模拟数据使用 `sports_match` 验证人工交叉特征；
- 当前优化器是 SGD，`weight_decay` 的具体含义与其他优化器可能不同。

FM 可以自动表达二阶交互，深度模型可以学习更复杂的非线性关系，因此不能把“LR 需要人工交叉”误写成“所有 CTR 模型都必须人工交叉”。

### 0.3 不同阶段关注的指标不同

| 阶段或任务 | 常见主要指标 | 说明 |
| --- | --- | --- |
| 召回 | Recall@K、Hit Rate、NDCG@K | 关注好候选能否进入候选集及位置 |
| CTR/CVR 排序 | AUC、GAUC、LogLoss、PR-AUC、ECE | 同时关注排序与概率质量 |
| 明确分类决策 | Precision、Recall、F1、成本函数 | 阈值必须结合误判成本选择 |
| 在线实验 | CTR、CVR、GMV、时长、留存等 | 最终由业务目标与护栏指标决定 |

“模型无关”不代表所有任务都照搬同一组指标。例如双塔召回模型通常不要求输出校准概率，LogLoss 就未必是核心指标；而广告价值计算可能直接使用 pCTR，概率校准便非常重要。

### 0.4 可复用的实验框架

以后比较任何模型，都可以复用下面的顺序：

```text
明确任务目标
→ 检查样本、标签和数据分布
→ 区分排序、概率与分类
→ 选择离线指标和业务指标
→ 固定数据切分并控制变量
→ 检查泛化、校准和稳定性
→ 解释收益、成本与适用边界
```

## 1. 为什么低 CTR 会让准确率失效

假设 10,000 次曝光中只有 100 次点击，真实 CTR 为 1%。一个模型如果永远预测“不点击”，准确率仍然可以达到：

```text
Accuracy = 9900 / 10000 = 99%
```

但它没有识别出任何点击用户，也无法为候选排序。准确率回答的是“最终分类对了多少”，CTR 模型更关心的是：

- 正样本能否排在负样本前面；
- 输出的点击概率是否可信；
- 在业务阈值下能找到多少有价值的正样本。

因此 CTR 评估通常至少观察 AUC 和 LogLoss，并根据任务补充 Precision、Recall、PR-AUC 和校准指标。

### 1.1 一次低 CTR 实验

在 LR 模拟数据生成器中设置：

```bash
uv run python -m models.lr.train --base-ctr 0.005
```

这里的 `0.005` 是其他特征产生影响前，参考曝光的基础点击概率，不是对最终整体 CTR 的硬性指定。用户兴趣、商品类别、匹配关系和晚间曝光等正向特征仍会提高部分样本的点击概率，因此 20,000 条样本的整体 CTR 为 0.86%，测试集实际 CTR 为 0.8%。

测试结果如下：

| 指标 | LR 模型 | 永远预测不点击 |
| --- | ---: | ---: |
| Accuracy | 0.992000 | 0.992000 |
| Precision | 0 | 0 |
| Recall | 0 | 0 |
| AUC | 0.782622 | 0.500000 |
| PR-AUC | 0.047474 | 0.008000 |

两个方法的 Accuracy 都是 99.2%，因为测试集中 99.2% 的样本恰好没有点击。只看 Accuracy，会错误地认为二者同样优秀；但 AUC 和 PR-AUC 表明，LR 已经学习到有效的相对排序，而永远预测不点击的模型没有任何区分能力。

### 1.2 为什么 AUC 很高，Recall 却是零

这两个指标没有矛盾，因为它们回答的问题不同。

AUC 使用连续概率，只关心正样本是否通常排在负样本前面。假设模型输出：

```text
正样本：0.08、0.06
负样本：0.02、0.01
```

它的排序可以很好，但若使用默认阈值 0.5：

```text
p >= 0.5 → 预测点击
p < 0.5  → 预测不点击
```

所有样本仍会被判为不点击，Recall 因而为零。低 CTR 模型输出普遍较小，0.5 通常不是有业务意义的固定阈值。

CTR 排序系统往往直接按 pCTR 排序或选择 Top-K，而不是先把概率转换成 0/1。只有在确实需要分类决策时，才应根据验证集和业务成本选择阈值，例如平衡 Precision 与 Recall，或满足某个召回率目标。

### 1.3 PR-AUC 为什么值得关注

ROC-AUC 观察正样本超过负样本的概率。在负样本极多时，大量容易区分的负样本可能让 ROC-AUC 看起来不错。PR-AUC 更关注：

```text
找出的正样本有多准？
全部正样本找回了多少？
```

随机排序的 PR-AUC 基线接近正样本比例。本次测试集正样本比例为 0.008，因此永远给出相同分数时 PR-AUC 为 0.008；LR 的 PR-AUC 为 0.047474，约为随机基线的 5.9 倍。它仍然不高，但在极低正样本比例下，比单看 Accuracy 更能反映正样本识别质量。

### 1.4 排序、概率和分类必须分开评估

本次模型的完整结果还包括：

```text
AUC           = 0.782622
PR-AUC        = 0.047474
LogLoss       = 0.045618
ECE           = 0.007035
预测 CTR      = 1.5035%
测试集实际 CTR = 0.8000%
```

它说明了三个不同层次：

| 层次 | 主要问题 | 对应观察 |
| --- | --- | --- |
| 排序 | 正样本能否排在负样本前面？ | AUC、PR-AUC |
| 概率 | 预测的 1% 是否真的约有 1% 点击？ | LogLoss、ECE、预测 CTR 与实际 CTR |
| 分类 | 在某个阈值下判定了多少正负样本？ | Precision、Recall、Accuracy |

这次 LR 排序有效，但平均预测 CTR 为 1.5035%，高于测试集实际 CTR 0.8%，说明概率仍有高估；默认 0.5 阈值又导致所有样本都被分类为负样本。一个模型可以同时“排序不错、概率有偏、固定阈值分类失败”，三者不能互相替代。

目前实验尚未进行负采样，因此概率高估不能归因于采样偏差。更合理的候选原因包括：极低 CTR 下正样本数量有限、40 轮 SGD 尚未充分拟合截距、训练集与测试集的随机波动，以及模型表达能力有限。后续应通过增加样本量、观察更多 Epoch、比较不同随机种子和检查校准曲线逐项验证，不能只凭一次输出确定原因。

### 问：类别不平衡会让模型完全学不到正样本吗？

不一定。BCE 会对每一条样本计算损失，只要正样本数量足够且特征中存在有效信号，模型仍然可以学习。但负样本远多于正样本时，训练计算会被大量简单负样本占据，模型选择和阈值判断也更容易受到分布影响。

类别不平衡不是“必须采样”的同义词。是否处理、怎样处理，要根据数据规模、训练成本、模型效果和概率用途决定。

## 2. 负采样解决什么问题

负采样是保留正样本，只抽取一部分未点击样本参与训练。例如原始数据有：

```text
正样本：1 万
负样本：99 万
```

若只保留 10% 的负样本，训练集变为：

```text
正样本：1 万
负样本：9.9 万
```

它的主要价值是：

- 减少训练数据量和计算成本；
- 减少大量重复、简单负样本对梯度的支配；
- 让模型在有限 Batch 中更频繁地看到正样本。

### 问：负采样会不会改变真实 CTR？

会。正样本全部保留、负样本只保留一部分后，训练集中的正样本占比会上升。模型在这个分布上学习到的概率通常不再等于线上真实点击概率。

假设每个负样本以概率 `s` 被保留，采样后模型输出：

```text
q = P(y = 1 | x, 样本被保留)
```

原始分布中的概率可以按采样率还原：

```text
p = s × q / (1 - q + s × q)
```

等价的 odds 形式更容易理解：

```text
p / (1 - p) = s × q / (1 - q)
```

当 `s < 1` 时，采样数据中的 `q` 通常高估真实概率 `p`。

### 问：负采样后 AUC 还能看吗？

通常仍可用于比较排序能力，因为单调的概率修正不会改变样本顺序。但评估集必须保持接近真实线上分布，不能用经过任意重采样的测试集直接报告线上 LogLoss、CTR 或校准结果。

推荐做法是：

```text
训练集：可以按明确规则负采样
验证集：尽量保留真实分布
测试集：保留真实分布，只用于最终评估
```

## 3. 样本权重和 `pos_weight` 是什么

除了删除负样本，还可以保留数据并调整不同样本对损失的贡献。

普通 BCE：

```text
L = -[y log(p) + (1-y) log(1-p)]
```

提高正样本权重后：

```text
L = -[αy log(p) + (1-y) log(1-p)]
```

其中 `α > 1` 会让模型更重视正样本预测错误。在 PyTorch 中，`BCEWithLogitsLoss(pos_weight=...)` 可以表达这种正类加权。

### 问：`pos_weight = 负样本数 / 正样本数` 是固定答案吗？

不是。这个比例是常见起点，但最终权重取决于优化目标和误判成本。权重越大，模型通常越倾向召回正样本，但可能增加误报，并改变概率校准。

### 问：使用 `pos_weight` 后输出还是点击概率吗？

模型输出仍在 0 到 1 之间，但经过加权损失训练后，它通常不再天然等于原始数据分布中的真实点击概率。若概率要参与 `pCTR × bid` 等价值计算，需要在真实分布的验证集上检查并校准。

### 问：负采样与样本权重怎样选择？

可以按目的区分：

| 方法 | 主要目的 | 主要代价 |
| --- | --- | --- |
| 负采样 | 降低数据量和计算成本 | 改变训练分布，需要概率修正 |
| `pos_weight` | 增强正样本对损失的影响 | 可能损害原始概率校准 |
| 每样本权重 | 修正采样偏差或表达业务价值 | 权重设计和方差控制更复杂 |

三者也可以组合，但必须记录采样率、权重定义和评估口径。

## 4. 概率校准为什么重要

AUC 只关心排序。如果对所有样本做一个严格单调变换，排序可能完全不变，AUC 也不变，但概率数值会改变。

例如两个模型可能具有相同排序：

```text
模型 A：0.01、0.05、0.10
模型 B：0.10、0.50、0.90
```

它们对“谁更可能点击”的判断一致，但对点击概率的判断完全不同。广告系统中，pCTR 可能参与出价和收益计算，因此概率偏差会进一步放大为业务决策偏差。

常见校准方法包括：

- 在真实分布验证集上进行 Platt Scaling；
- 使用 Isotonic Regression；
- 根据已知负采样率进行理论修正；
- 按人群、场景或概率分桶检查预测 CTR 与实际 CTR。

校准模型的拟合数据也必须与训练数据分开，否则会产生新的过拟合。

## 5. 什么是过拟合

过拟合指模型不仅学习了稳定规律，还记住了训练数据中的偶然噪声。典型表现是：

```text
Train Loss 持续下降
Validation Loss 先下降后上升
```

LR 是线性模型，但并不意味着不会过拟合。高维稀疏 CTR 特征中可能包含大量 ID、组合特征和低频类别；当参数很多、样本有限时，LR 同样可能为偶然相关性学习出很大的权重。

### 问：为什么当前 LR 实验没有明显过拟合？

当前实验只有 5～6 个特征和 20,000 条模拟样本，数据规律稳定，模型容量很小，所以 Train Loss 与 Validation Loss 很接近。它适合验证训练流程，却不能代表工业级高维稀疏数据的难度。

## 6. L2 正则化如何限制模型

L2 在原始损失上增加权重平方和：

```text
L_total = L_BCE + λ Σ wᵢ²
```

权重越大，惩罚增长越快。它倾向于让所有权重保持较小，而不是直接变成零。

L2 的作用包括：

- 限制模型对单个特征的过度依赖；
- 降低参数对训练样本噪声的敏感度；
- 在相关特征之间形成更平滑的权重分配。

PyTorch 优化器常用 `weight_decay` 配置 L2 风格的权重衰减：

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.05,
    weight_decay=1e-4,
)
```

实践中应确认所用优化器的 weight decay 定义。SGD 中它与常见 L2 更新等价；AdamW 使用解耦权重衰减，不能简单当作“在损失中加同一个 L2 项”来理解。

### 问：偏置 `bias` 也要正则化吗？

通常不会对偏置施加与权重相同的正则化，因为偏置主要表达整体基准率。复杂模型还常把 Embedding、归一化参数和其他参数分组设置不同的 weight decay。

## 7. L1 正则化有什么不同

L1 使用权重绝对值之和：

```text
L_total = L_BCE + λ Σ |wᵢ|
```

它会推动一部分不重要的权重变为零，因此常与稀疏性和特征选择联系在一起。

| 对比项 | L1 | L2 |
| --- | --- | --- |
| 惩罚形式 | `|w|` | `w²` |
| 典型结果 | 部分权重变为零 | 权重整体变小 |
| 常见用途 | 稀疏化、特征选择 | 稳定训练、控制权重 |
| 优化特性 | 零点不可导，通常用次梯度或专门方法 | 平滑、易于优化 |

### 问：正则化越强越好吗？

不是。`λ` 太小无法抑制过拟合，太大会把有效信号也压制掉，导致欠拟合。正则化强度属于超参数，应在验证集上选择，测试集只用于最终报告。

## 8. Early Stopping 解决什么问题

Early Stopping 持续观察验证集指标。当指标在若干轮内不再改善时停止训练，并恢复到最佳轮次的模型参数。

一个典型流程是：

```text
每轮训练结束
→ 计算 Validation Loss
→ 如果改善，保存 checkpoint 并重置 patience
→ 如果连续多轮未改善，停止训练
→ 加载最佳 checkpoint
```

### 问：Early Stopping 可以替代正则化吗？

不能完全替代。Early Stopping 限制模型继续适应训练数据，L1/L2 直接限制参数。它们从不同角度控制模型复杂度，通常可以共同使用。

### 问：为什么不能根据 Test Loss 决定停止？

一旦反复使用测试集选择训练轮数、正则化强度或模型版本，测试集就参与了模型开发，最终结果会对测试集过拟合。模型选择必须使用验证集。

## 9. 推荐的实验设计

为了把这些概念变成证据，可以在当前 LR 基线上逐步增加实验：

1. 降低模拟数据的 CTR，展示准确率陷阱。
2. 只对训练集负采样，保持验证集和测试集的真实分布。
3. 比较未修正概率与按采样率修正后的 LogLoss、ECE 和预测 CTR。
4. 对比无正则、不同 L2 强度和 L1 正则化。
5. 增加噪声特征，观察 Train/Validation Loss 与权重变化。
6. 加入 Early Stopping，并记录最佳 Epoch，而不是只记录最后一个 Epoch。

实验必须保持相同的数据切分和随机种子，每次只改变一个因素，避免无法归因。

## 10. 最终检查清单

面对低 CTR 数据时，需要回答：

- 准确率是否被多数负样本误导？
- 训练集是否进行了负采样，采样率是多少？
- 验证集和测试集是否保留真实分布？
- 是否使用 `pos_weight` 或样本权重，业务含义是什么？
- 模型概率是否经过采样修正或校准？
- AUC、LogLoss、PR-AUC 和 ECE 分别说明什么？

面对过拟合时，需要回答：

- Train Loss 和 Validation Loss 是否开始分叉？
- 参数规模是否相对数据量过大？
- 是否存在大量低频、噪声或泄漏特征？
- L1/L2 的强度是否通过验证集选择？
- 是否保存并恢复了最佳 Epoch？
- 测试集是否被错误地用于调参？

## 11. 总结

1. 低 CTR 场景中，高准确率可能只是多数类造成的假象。
2. 负采样主要降低计算成本，但会改变训练分布和概率含义。
3. `pos_weight` 强调正样本损失，却不保证输出仍然自然校准。
4. 排序指标与概率指标不能互相替代，校准应在真实分布上评估。
5. LR 在高维稀疏特征上同样可能过拟合。
6. L1 倾向产生稀疏权重，L2 倾向让权重整体保持较小。
7. Early Stopping 使用验证集选择最佳轮次，不能偷看测试集。
8. 采样、加权、正则化和校准都必须记录口径，并通过控制变量实验验证。
