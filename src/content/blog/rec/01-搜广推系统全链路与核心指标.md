搜广推系统的任务可以用一句话概括：

> 在很短的时间内，从海量候选中选出少量最适合当前用户和场景的结果，并按照业务目标排序。

这篇文章先建立一张完整地图：系统为什么要分级，每一级在做什么，行为数据怎样变成训练样本，以及 CTR、CVR 等指标究竟表示什么。

## 1. 搜、广、推的共性与差异

三者的核心都是候选检索与排序，但输入和优化目标不同。

| 场景 | 主要输入 | 关键目标 |
| --- | --- | --- |
| 搜索 | 用户 + Query + 文档/商品 | 相关性、满足明确需求 |
| 推荐 | 用户 + 上下文 + 内容/商品 | 推断兴趣、长期体验 |
| 广告 | 用户 + 上下文 + 广告 | 用户体验、广告主价值、平台收益 |

搜索有明确 Query，相关性是基本约束；推荐没有明确 Query，需要从行为中推断兴趣；广告还要考虑出价、预算、ROI 和投放节奏。

## 2. 为什么需要多级漏斗

假设内容库有一千万个候选，首页只需要展示十个。如果让复杂模型逐个评估一千万个候选，响应时间和计算费用都无法接受。

工业系统因此把计算分层：

```text
千万级内容库
    ↓ 召回
数千个候选
    ↓ 粗排
数百个候选
    ↓ 精排
数十个候选
    ↓ 重排
最终展示列表
```

这是效果、延迟和成本的折中：

```text
候选越多 → 单个候选的计算必须越便宜
候选越少 → 可以使用越丰富的特征和越复杂的模型
```

### 2.1 召回：快速找到可能合适的候选

召回从海量内容中取回数百到数千个候选，核心是快速和尽量不遗漏好结果。

它通常不会遍历所有内容，而是通过索引或多路通道直接获取候选：

- 兴趣召回；
- 协同过滤；
- 热门召回；
- 关注作者召回；
- 双塔向量召回；
- ANN 近似最近邻检索。

召回如果丢掉了一个好候选，下游模型再强也无法把它找回来。

### 2.2 粗排：用较低成本继续缩小范围

粗排对召回结果进行轻量打分，淘汰明显不合适的候选。它比召回使用更多特征，但模型仍然必须快。

### 2.3 精排：准确预测用户行为

精排面对的候选已经较少，可以使用用户特征、候选特征、上下文、行为序列和特征交互，预测点击、转化、时长等目标。

### 2.4 重排：优化整个结果列表

精排更像是单独估计每个候选的价值，重排则关注整个列表，并处理：

- 内容多样性与新鲜度；
- 相似内容或作者打散；
- 广告密度与展示约束；
- 探索与利用的平衡；
- 平台规则与生态约束。

## 3. 从曝光到转化的行为漏斗

一条常见的用户行为链路是：

```text
曝光 → 点击 → 加购/提交 → 支付/注册等转化
```

**曝光**表示用户真正获得了看到候选的机会。服务端返回了二十条内容，不等于二十条都发生了曝光；用户可能只滑动到第五条。

**转化**由业务目标定义，可以是支付、注册、安装、预订、提交线索或订阅。点击通常只表示兴趣，转化才更接近最终业务价值。

## 4. 数据是怎样产生的

完整数据链路通常由三类数据共同组成。

### 4.1 客户端埋点

记录用户看到和操作了什么，例如曝光、点击、停留、播放、点赞和加购。

### 4.2 服务端日志

记录系统做了什么，例如召回了哪些候选、模型分数、最终排名、模型版本和实验分组。

### 4.3 业务数据库

确认最终发生的事情，例如订单、支付、退款和注册。金额和支付结果通常不能仅依赖客户端埋点。

这些数据通过 `request_id`、`user_id`、`item_id`、`click_id` 和时间等字段串联，再经过校验、去重、关联、归因和标签构造，形成训练样本。

## 5. CTR：曝光后发生点击的概率

CTR 是 Click-Through Rate，即点击率：

```text
CTR = 点击次数 / 曝光次数
```

历史 CTR 是统计量，而 CTR 模型要预测的是当前这次曝光的点击概率：

```text
pCTR = P(点击=1 | 用户、候选、上下文、曝光)
```

CTR 训练样本来自有效曝光：

```text
曝光后点击   → y = 1
曝光后未点击 → y = 0
没有曝光     → 未知，不能直接当作负样本
```

训练形式是二分类，但模型输出的是概率，线上主要使用概率比较候选，而不是以 `0.5` 为阈值硬分成“点击”和“不点击”。

## 6. CVR：点击后发生转化的概率

CVR 是 Conversion Rate，在广告排序中常指点击后转化率：

```text
CVR = 转化次数 / 点击次数
```

CVR 模型预测：

```text
pCVR = P(转化=1 | 已点击、用户、候选、上下文)
```

传统 CVR 训练只使用已点击样本：

```text
点击后转化   → y = 1
点击后未转化 → y = 0
```

CVR 通常比 CTR 更难：

- 点击数量少于曝光，转化更加稀疏；
- 用户可能数小时或数天后才转化，存在延迟反馈；
- 训练数据只来自被旧系统展示并被点击的候选，存在样本选择偏差。

## 7. CTCVR：从曝光到转化

CTCVR 表示从曝光开始最终发生转化的概率：

```text
pCTCVR = P(转化=1 | 曝光)
```

在“先点击，后转化”的链路下，根据条件概率：

```text
pCTCVR = pCTR × pCVR
```

例如：

```text
pCTR = 10%
pCVR = 5%
pCTCVR = 10% × 5% = 0.5%
```

一万次类似曝光大约产生五十次转化。

## 8. 容易混淆的计费和业务指标

CTR、CVR 描述行为效果；CPM、CPC、CPA 则更多描述计费或成本。

| 指标 | 含义 | 常见计算 |
| --- | --- | --- |
| CTR | 点击率 | 点击 / 曝光 |
| CVR | 点击后转化率 | 转化 / 点击 |
| CTCVR | 曝光后转化率 | 转化 / 曝光 |
| CPM | 每千次曝光费用 | 费用 / 曝光 × 1000 |
| CPC | 单次点击成本 | 费用 / 点击 |
| CPA | 单次转化成本 | 费用 / 转化 |
| ROI | 投资回报比 | 收益 / 成本，口径需业务约定 |

广告系统可能使用类似下式的预期价值：

```text
预期点击价值 ≈ pCTR × 单次点击价值
预期转化价值 ≈ pCTR × pCVR × 单次转化价值
```

真实系统还会结合出价、预算、校准、投放速度、用户体验和平台规则，不能把这些简化式当作完整的线上排序公式。

## 9. 为什么曝光数据天然有偏

用户只能对系统展示过的内容产生反馈：

```text
旧模型选择展示内容
    ↓
用户只反馈这些内容
    ↓
这些反馈训练新模型
```

如果旧系统很少曝光冷门作者，这些作者就很难积累点击，新模型可能继续认为他们价值不高。这是曝光偏差或选择偏差。

因此要牢记：

> 未曝光不等于负反馈；曝光后未点击才能在当前口径下构成 CTR 负样本。

## 10. 一张图回顾全链路

```text
用户请求
  ↓
召回 → 粗排 → 精排 → 重排
  ↓
候选被真实曝光
  ├─未点击 → CTR 负样本
  └─点击   → CTR 正样本
       ├─未转化 → CVR 负样本
       └─转化   → CVR 正样本
  ↓
埋点 + 服务端日志 + 业务数据库
  ↓
校验、去重、归因、构造标签
  ↓
训练新模型并再次服务线上请求
```

## 11. 总结

1. 多级漏斗是效果、延迟和计算成本的折中。
2. 召回重覆盖与速度，精排重预测精度，重排重列表整体价值。
3. CTR 是点击/曝光，CVR 是转化/点击，CTCVR 是转化/曝光。
4. 在简化链路中，`pCTCVR = pCTR × pCVR`。
5. 点击表示兴趣，转化表示业务定义的目标行为。
6. 客户端记录用户行为，服务端记录系统决策，业务库确认最终结果。
7. 未曝光候选的用户偏好是未知的，不能直接当作负样本。
