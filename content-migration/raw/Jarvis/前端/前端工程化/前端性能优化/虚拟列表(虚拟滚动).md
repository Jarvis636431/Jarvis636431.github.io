 当前端渲染大量数据的时候，如果全部渲染，页面会变得非常卡顿，所以就诞生了虚拟滚动这一思想，即**只渲染页面可视窗口内的部分列表项**
### 1. 基本原理

1. 计算「可视区域能容纳的元素数量」 = visibleCount = containerHeight / itemHeight。
2. 计算「开始索引」 = start = Math.floor(scrollTop / itemHeight)。
3. 计算「结束索引」 = end = start + visibleCount + buffer（加缓冲区避免闪烁）。
4. 渲染「start;end」区间的数据；
5. 用一个「占位 div」设置 height = total * itemHeight 以维持滚动条。
6. 内层列表整体 transform: translateY(start * itemHeight) 以偏移到正确位置。
### 2. 面试问题

| 常见追问                 | 回答                                                   |
| -------------------- | ---------------------------------------------------- |
| 为什么能减少性能开销？          | 只渲染可视区域的 DOM（几十个），不渲染全部几千个节点。                        |
| 滚动时为什么不卡顿？           | 重绘的节点数量恒定，布局/回流代价固定。                                 |
| 滚动条长度如何保持？           | 用一个高度为总长度的“占位 div”维持。                                |
| 动态高度怎么做？             | 高度缓存 + 滚动累计高度表（binary search 定位 startIndex）。         |
| 为什么要加 buffer？        | 防止快速滚动导致内容闪烁。                                        |
| 可以和 keep-alive 一起用吗？ | 一般不需要缓存整个组件，可自己实现 item-level 缓存。                     |
| React / Vue 实现差异？    | 思路相同，React 用 state + scroll 事件；Vue 用 computed + ref。 |
